## NOT verified - do not assume these work
1. **No deployment to Cloudflare** was performed (no credentials). `scripts/deploy.sh` is unrun.
2. **No real Meta/WhatsApp traffic.** Every WhatsApp test uses a mocked Graph API. Webhook payload shapes (especially `smb_message_echoes`, `smb_app_state_sync`, `history`, `account_update`), error codes (`131047`, `131053`, …), `is_on_biz_app`/`platform_type` fields, Graph version `v23.0`, and media limits (MP4/3GPP, 16 MB) come from documentation as understood at writing time. Follow the real-integration procedure in `docs/WHATSAPP_COEXISTENCE_SETUP.md`.
3. **The WPF License Generator window** (`SmartManager.LicenseGenerator`) has **not been compiled or run**: the sandbox's .NET SDK lacks the Windows Desktop SDK and Microsoft's installer host is blocked. Only XAML well-formedness and handler/name consistency were checked. The portable core (what actually signs licenses) is tested. No `.exe` was produced; build it on Windows (`scripts/build-license-generator.sh`).
4. **Embedded Signup / automated Coexistence onboarding is not implemented** (administrator-assisted onboarding only).
5. Free-plan behaviour: CPU-time (login hashing), D1/Queue daily limits were reasoned about and are monitored via estimates, **not measured** on Cloudflare. Local workerd does not enforce Free-plan CPU limits.
6. Not tested: Lighthouse PWA audit, real iOS/Android install, Safari; accessibility audit beyond semantic labels/contrast choices; load/performance; Queue consumer behaviour on real Cloudflare Queues (tests call the consumer function directly with captured messages; retry/DLQ wiring is configuration only).
7. Notification email is stored but unused. iOS splash images are not generated. No MFA. No independent security review.
